С явного разрешения пользователя MIRROR X использует **отдельную схему mirror_x** в существующем Supabase-проекте **Jetuu**, ref `edpuovkgoisyzpguksdi`. Создание нового проекта было отклонено из-за лимита двух активных бесплатных проектов. Тариф не менялся, другие проекты не приостанавливались и не удалялись.

Существующие таблицы, views и Auth-настройки Jetuu не изменялись. Контрольная подпись существующих public-объектов до и после: `8072d96d8afc3dde438e5ab7bda99c17`. Исходных public-таблиц:99. Новые public views и RPC имеют префикс mx_; данные и индексы находятся в mirror_x.

В базе503 компании,3 годовых набора фактов и1 опубликованный PRELIMINARY snapshot `MX-3777d2e495a9`. Explorer и API фильтруют/сортируют/пагинируют в БД. Company/Valuation/Compare и brief читают общую серверную repository. Публичные данные кэшируются120 секунд. Наличие env включает реальную Supabase; при ошибке соединения возвращается503, а статус CONNECTED не подставляется.

## Auth и личные данные

- Email/password Supabase Auth: вход, регистрация с действующими правилами email confirmation, выход, PKCE callback.
- В бесплатной конфигурации Auth общий с Jetuu; cookies на домене MIRROR X отдельные. Можно использовать существующий аккаунт. После подтверждения почты следует вернуться в MIRROR X и войти.
- Watchlist, заметки и модели сохраняются в личной записи владельца. Заметку в облаке сохраняют отдельной кнопкой.
- Старые localStorage-записи доступны без входа. Перенос атомарен для каждой записи, повторяем и не перезаписывает уже существующее облачное исследование. Локальные оригиналы остаются.
- Заявка пилота может быть сохранена авторизованным пользователем; письма от имени пользователя автоматически не отправляются.

## Защита

RLS на всех6 новых таблицах, минимальные GRANT, security_invoker на5 API views и RPC. Сервер использует getUser для проверки реальной сессии. Owner передаётся из auth.uid(), не из тела запроса или user_metadata. Межпользовательское чтение/запись/удаление и смена owner отвергаются. Только опубликованные snapshot доступны анонимно.

Частные API: Cache-Control private,no-store + Vary Cookie. POST/DELETE проверяют Origin и JSON, ограничивают тело20KB. Модели проходят общую Zod/DCF-валидацию. Ограничение120 сохранений в минуту на пользователя обеспечивается БД; старые bucket-строки владельца очищаются при следующих записях. Service-role не нужен и не используется.

## Развёртывание и откат

В Vercel mirror-x настроены только NEXT_PUBLIC_SUPABASE_URL и NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY для production/preview. Публичный ключ предназначен для клиента; приватность обеспечивают Auth/RLS. Пароли тестовых пользователей не попадают в клиентскую сборку.

Сначала проверен Preview; production собирается из основной feature-ветки без QA route. Дополнительные платные ресурсы и новые тарифы не включались. Автоматическая Git-связь Vercel через этот connector не настроена: source deployments запускаются по проверенному Git SHA/ветке через API. GitHub Actions проверяет код отдельно.

Откат: вернуть прежний deployment либо убрать облачные env и пересобрать локальный режим. Схема и пользовательские облачные записи при этом сохраняются. Удаление схемы/таблиц не является частью автоматического отката.

Конкурсная финализация остаётся отдельной: закрытие02.11 ещё впереди, OHLCV и проверенные Buy не выдумываются.
